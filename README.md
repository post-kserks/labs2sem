# Предметная область "Школа" (Семинар 4: Полиморфизм)

Данный проект демонстрирует ключевые принципы объектно-ориентированного программирования (ООП) на языке C++ в предметной области "Школа". Помимо базовых связей между объектами, в проект добавлены абстрактный интерфейс, динамический полиморфизм и полиморфное хранение объектов через умные указатели.

## Реализованные концепции ООП

В коде продемонстрированы основные отношения и механизмы ООП:

1. **Абстрактный интерфейс и динамический полиморфизм**
   - `Person` — абстрактный базовый класс с чистыми виртуальными методами:
     - `printInfo()`
     - `primaryResponsibility()`
   - В `Person` объявлен виртуальный деструктор.

2. **Иерархия наследования** (Отношение "*is-a*")
   - `Person` -> `Employee` -> `Teacher` (три уровня)
   - `Student` наследуется от `Person`
   - Во всех производных классах используются `override`.

3. **Ассоциация** (Слабая независимая связь)
   - Классы: `Student` (Ученик) и `Teacher` (Учитель)
   - Сущности существуют независимо друг от друга. Ученик просто хранит указатель на своего классного руководителя. Уничтожение ученика не влечет за собой уничтожения учителя и наоборот.

4. **Агрегация** (Отношение "*has-a*", независимое время жизни)
   - Классы: `School` (Школа) и `Teacher` (Учитель)
   - Школа имеет коллекцию учителей (хранит указатели на объекты). При закрытии или сносе здания школы (`~School()`) сами объекты учителей остаются в памяти программы и продолжают "жить".

5. **Композиция** (Отношение "*part-of*", жестко связанное время жизни)
   - Классы: `School` (Школа) и `Classroom` (Аудитория)
   - Школа физически содержит в себе помещения. Аудитории хранятся как `std::unique_ptr<Classroom>` и уничтожаются автоматически вместе со школой.

6. **Делегирование** (Передача ответственности)
   - Метод: `conductLessons()` в классе `School`
   - Класс "Школа" не реализует логику преподавания внутри себя. Она формулирует задачу и полностью делегирует (поручает) её выполнение объектам учителей, вызывая у них метод `teach()`.

7. **Полиморфное хранение и RTTI**
   - В `main.cpp` используется `std::vector<std::unique_ptr<Person>>` для хранения объектов разных типов (`Teacher`, `Student`).
   - Показана работа `typeid` и `dynamic_cast` для безопасного доступа к специфичным методам.

## Сборка и запуск проекта

Проект использует утилиту `make` для автоматической сборки. Компиляция выполняется компилятором `g++` с поддержкой стандарта `c++17`.

### Доступные команды:

- **Собрать и сразу запустить проект** (рекомендуется):
  ```bash
  make run
  ```

- **Только скомпилировать проект** (создаст исполняемый файл `./school_app`):
  ```bash
  make
  ```

- **Очистить директорию от временных файлов и бинарника:**
  ```bash
  make clean
  ```

## Структура файлов

- `Person.hpp` — Абстрактный интерфейс участника школы.
- `Employee.hpp` — Сотрудник школы (уровень 1 наследования).
- `Teacher.hpp` — Учитель (уровень 2 наследования), поддержка делегирования.
- `Student.hpp` — Класс ученика (демонстрация ассоциации).
- `Classroom.hpp` — Класс аудитории (демонстрация композиции).
- `School.hpp` / `School.cpp` — Класс школы (агрегация, композиция, делегирование).
- `main.cpp` — Точка входа с демонстрацией полиморфной функции, полиморфного контейнера и RTTI.
- `Makefile` — Скрипт сборки.
