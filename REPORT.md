# Отчет по лабораторной работе №1
## Тема: Создание кроссплатформенной статической библиотеки на C++

### 1. Цели и задачи
**Цель работы:** Приобретение навыков проектирования классов, создания статических библиотек и организации процесса сборки проекта с использованием `Makefile`.

**Задачи:**
1. Разработать класс `GeoLocation` для работы с географическими координатами.
2. Реализовать инкапсуляцию, конструкторы, get/set методы и перегрузку операторов.
3. Реализовать алгоритм вычисления расстояния между точками на сфере (формула Хаверсина).
4. Оформить код в виде статической библиотеки.
5. Создать демонстрационное приложение и настроить автоматическую сборку.

### 2. Логика программы и реализация
Класс `GeoLocation` инкапсулирует два приватных поля типа `double`: `latitude` (широта) и `longitude` (долгота).

**Основные компоненты:**
- **Конструкторы:** Обеспечивают инициализацию объектов (по умолчанию в 0,0 или заданными значениями).
- **Математическая логика:** Метод `distanceTo` реализует формулу Хаверсина. Это необходимо, так как обычная евклидова метрика не подходит для вычислений на поверхности Земли.
- **Статические инструменты:** Метод `fromDMS` позволяет удобно преобразовывать человекочитаемый формат (градусы, минуты, секунды) в десятичный вид, используемый в вычислениях.
- **Интерфейс:** Перегруженный оператор `<<` и метод `display` позволяют легко отслеживать состояние объекта.

### 3. Ход мыслей и проектные решения
При написании кода я придерживался принципа **минимальной достаточности** и **чистоты кода**:
- Для сравнения координат (тип `double`) в операторе `==` использовалась проверка с погрешностью (`epsilon`), так как точное сравнение чисел с плавающей точкой в C++ ненадежно.
- Математические константы (число Пи, радиус Земли) вынесены в начало файла реализации для удобства правки.
- Структура проекта была разделена на интерфейс (`.h`), реализацию (`.cpp`) и клиентский код (`main.cpp`), что является стандартом промышленной разработки.

### 4. Трудности и их решение
1. **Точность вычислений:** При реализации формулы Хаверсина важно использовать радианы вместо градусов. Для этого была создана вспомогательная функция `toRadians`.
2. **Кроссплатформенность:** Использование стандартных библиотек C++ (`cmath`, `iostream`) и классического `Makefile` гарантирует, что проект соберется как на macOS, так и на Linux без изменений.
3. **Конфликты Git:** В процессе работы возникла ситуация, когда удаленная ветка содержала коммиты, конфликтующие с локальными. Проблема была решена выполнением `force push` после согласования с пользователем, так как локальная версия была целевой и полной.
